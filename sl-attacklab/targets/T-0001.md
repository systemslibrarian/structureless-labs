# Target T-0001

Frozen:       [`sl-kem/spec/SPEC-000.md`](../../sl-kem/spec/SPEC-000.md) at the commit
              that introduces SPEC-000 (the first commit on `main` to contain that
              file). `git log -- sl-kem/spec/SPEC-000.md` resolves the exact tree.

Claim:        The algorithmic SHAPE in SPEC-000 follows the unstructured-LWE KEM family
              with a Fujisaki-Okamoto transform for IND-CCA2, and the three procedures
              (`KeyGen`, `Encaps`, `Decaps`) are mutually consistent at the shape level
              — i.e. an honest `Decaps(sk, Encaps(pk).c)` recovers the encapsulated
              shared secret `K` modulo a decryption-failure event whose probability
              is `TODO` until parameters land.

              Evidence grade: **D** — structural assertion. No security level claimed,
              no parameter set bound, no implementation produced. Per
              [`EVIDENCE-GRADING.md`](../../sl-researchkit/checklists/EVIDENCE-GRADING.md),
              "Reasoned argument, untested" is grade D.

Not claiming: - **NO security level** (`λ` unset in SPEC-000).
              - **NO decryption-failure probability bound** (`δ` unset; until it lands
                AND satisfies the D'Anvers et al. 2019 adaptive-failure constraint, no
                CCA-security strength can be argued numerically).
              - **NO parameter set** (`n, m, q, χ, η` all `TODO`).
              - **NO concrete implementation behavior** (no reference code; no vectors —
                see `sl-vectors/sl-kem/SPEC-000/README.md`; no measured timings — see
                `sl-bench/sl-kem/SPEC-000/INTERPRETATION.md`).
              - **NO IND-CCA2 SECURITY GUARANTEE** — only the FO transform *shape* is
                fixed; until `χ`, the encoder `E/D`, and the parameter set land, the
                CCA argument is structural and not numerical.
              - **NO ENDORSEMENT BORROWED** — Wang et al.'s S-Cloud+ is a separate
                construction in the same family; SPEC-000 inherits none of its
                review status (see [root README §Lineage](../../README.md#lineage-and-related-prior-work)).

Open since:   2026-06-09

Status:       **Open — structural target.**

              **No cryptanalytic attack can be attempted against T-0001** because the
              target makes no numerical claim. The honest break-it-first surface
              against T-0001 is purely structural:

                1. **Consistency:** does `Decaps(sk, Encaps(pk).c)` *as written* in
                   SPEC-000 recover `K`? Trace it by hand or in a symbolic execution.
                2. **Decision-point completeness:** SPEC-000 enumerates open decisions.
                   Are any silently presupposed by the SHAPE? Find one that is.
                3. **FO fidelity:** does the SPEC-000 `Encaps`/`Decaps` pair match the
                   reference Fujisaki-Okamoto transform precisely enough that a
                   well-meaning implementer cannot accidentally drop the re-encryption,
                   the constant-time compare, or the implicit rejection?
                4. **Serialization ambiguity (forward):** SPEC-000 leaves serialization
                   `TODO`; a finding could pre-empt the next decision by enumerating
                   the choices and the canonical-encoding traps in each.

              Findings of any of the above types are appropriate `F-NNNN` filings
              against T-0001. **Cryptanalytic findings (BKZ runs, dual-attack
              estimates, decryption-failure attack instantiations) belong against a
              future T-NNNN that freezes a parameterized `SPEC-NNN`, not against
              T-0001.**

History:      T-0001 is the lab's first frozen attack target. Per the AI-vs-AI
              cryptanalysis workflow
              ([`sl-researchkit/workflows/AI-VS-AI-CRYPTANALYSIS.md`](../../sl-researchkit/workflows/AI-VS-AI-CRYPTANALYSIS.md)),
              a round can only be run against a frozen target. The first round
              (`round-0000.md`) is **NOT** run against T-0001 because the
              cryptanalytic surface is intentionally absent; the first round happens
              the month T-NNNN with a parameter set lands.
