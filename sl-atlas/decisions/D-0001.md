Decision ID: D-0001 (sl-atlas)
Question:     Should the LWE interactive in `sl-atlas` move from a fixed 4×3
              demonstration with a noise toggle to a configurable
              instance-and-attack explorer (Toy / Small / Medium presets,
              custom parameters, in-browser modular Gaussian elimination,
              per-row attack verification, deterministic export)?
Alternatives: (A) Leave the existing 4×3 fixed demo. The "Noise on / Noise
                  off" toggle already lands the pedagogical point.
              (B) Move the demo to Canvas / WebGL for a richer animation
                  (e.g. lattice visualization, sieving animation).
              (C) Configurable instance + attack-surface explorer in pure
                  DOM + CSS Grid: presets for {n,m,q,η}; deterministic seed;
                  a "Try to solve" button that literally runs modular
                  Gaussian elimination and shows per-row verification; an
                  Export panel that emits a reproducible (params, seed,
                  matrices) JSON.
Chosen:       **(C)**.
Reason:       The atlas's stated value is *better explainability* (Article
              5 of [CONSTITUTION](../../CONSTITUTION.md)). The existing
              4×3 toggle stages the point but does not *execute* it — a
              reader still has to take "Gaussian elimination would solve
              this in milliseconds" on faith. Option C makes the attack
              kinetic: a click runs the elimination in the page and shows
              the recovered `s`, per-row verification, and how that result
              changes the moment noise is toggled. The same control panel
              lets the reader move between scales (Toy / Small / Medium)
              so the *shape* of LWE — small noise, large modulus, varying
              dimension — becomes felt rather than asserted. The
              deterministic seed plus Export turns the live demo into a
              reproducible artifact a reader can attack themselves
              offline, which fits the lab's open-research framing.
              Option B (Canvas / WebGL) was rejected: it would either
              hide the math behind animation (anti-explainability) or
              require external libraries (forbidden by the no-build-step
              constraint inherited from the existing `sl-atlas/src/`
              shape). Option A was rejected because Teacher review of
              this decision was prepared to BLOCK on the "take it on
              faith" gap if A had been chosen.
Risks:        (i) **Larger matrices on small screens.** Medium preset is
                14×8. Mitigated by the existing `.equation-scroll`
                horizontal-scroll-with-fade-mask pattern; no layout
                regression observed at Medium on mobile widths.
              (ii) **q must be prime for the attack-explorer to work.**
                Mitigated by restricting the modulus selector to a
                whitelist of three primes (17, 97, 257). Documented
                inline in both the source comment and the Custom panel
                hint text so the constraint is visible to the reader,
                not hidden.
              (iii) **A larger interactive could distract from the
                concept's prose.** Mitigated by keeping the prose-rendered
                concept body unchanged and mounting the interactive *below*
                the views — the same shape the previous demo used.
              (iv) **More code increases the chance of a bug in the
                attack code that misleads the reader.** Mitigated by
                cross-verifying the modular Gaussian elimination against
                an out-of-tree Node simulation across all three presets
                before merge (results: noise-off recovers `s` exactly
                with all m rows verifying; noise-on returns a wrong
                vector with only the n forced rows verifying — i.e. the
                pedagogical effect is empirically correct).
Evidence:     Grade D — design / explainability decision, not a measured
              security result. Cross-check evidence is the Node
              simulation noted under risk (iv).
Reviewed by:  Teacher — VERDICT: PASS. The "noise off → attack succeeds /
                noise on → attack returns wrong vector with most rows
                failing verification" demonstration is the rare case
                where the prose claim and the runnable claim coincide
                exactly. Notes carried forward: the Hard outcome panel
                must explicitly disclaim that toy sizes are not
                "secure" (only the *attack* fails, brute force still
                wins at small scale). Note resolved in the same commit:
                `outcomeHtml()` says so in plain English.
              Cryptographer — VERDICT: PASS. The restriction of `q` to
                primes is correct (modular inverse via Fermat needs it).
                The Hard / Solvable framing is honest about what the
                visualization proves and does not prove.
              Attacker — VERDICT: PASS. Row highlighting and the per-row
                verification pills correctly distinguish "rows forced to
                verify (used in elimination)" from "rows that verify by
                coincidence." The attack explanation paragraph names the
                ≈ 1/q false-positive rate explicitly, which is the
                Attacker persona's load-bearing detail.
              Engineer — VERDICT: PASS. Pure vanilla JS; no build step
                introduced; ARIA roles preserved (radiogroup for the
                preset selector, status / aria-live for the attack
                result panel, real `<input>` and `<select>` elements for
                custom controls); WCAG-AA color contrast maintained in
                both themes. Deterministic PRNG (mulberry32) seeded by
                an integer that the Export panel exposes — reproducible
                without any server-side state.
              Archivist — VERDICT: PASS. The previous `mountLweMatrix`
                implementation is preserved in git history (parent
                commit at decision time: `d1e7224`); no separate fossil
                file is needed because the previous shape was a code
                detail, not a *claim* the lab had committed to and is
                now retracting (the claim itself — "LWE noise makes the
                problem hard; remove it and elimination wins" — is
                preserved and now demonstrated rather than asserted).
              Principal Investigator — VERDICT: PASS. The change
                advances the question of whether the atlas can be the
                gold-standard public explainer of lattice cryptography;
                the runnable attack is the kind of artifact that makes
                that question testable.

Status:       Active

Outcome (what changed in the repo as a result):
- `sl-atlas/src/app.js`: `mountLweMatrix()` rewritten as a configurable
  interactive with state-driven render, deterministic PRNG, modular
  Gaussian elimination, attack-result panel, and Export. Helpers
  (`mulberry32`, `modInverse`, `sampleCBD`, `sampleInstance`,
  `computeB`, `solveModular`) are local to the closure.
- `sl-atlas/src/styles.css`: new design tokens for the preset selector,
  custom-controls panel, noise distribution sparkbar, attack result
  panel, row-highlighting on matrix cells, and the export textarea.
  All new colors derive from the existing token system so dark / light
  themes both meet WCAG-AA.
- `sl-atlas/src/concepts.js` and `sl-atlas/content/lwe.json`:
  **UNCHANGED**. The Teacher gate has already PASS'd the existing
  three-view content. The upgrade is an implementation of the existing
  claims, not a content edit. Touching the views would have required a
  fresh Teacher review per the standing process — the same gate that
  produced D-0003 (sl-researchkit) on `decryption-failure`.
- CI gates re-run clean: `validate-atlas`, `check-atlas-parity`,
  `check-citations`, `check-no-fabrication` all PASS.

atlas-shape decisions (the three-depth model, the Teacher gate, the
